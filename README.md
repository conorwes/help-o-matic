# Help-O-Matic

Help-O-Matic generates placeholder HTML help-topic skeleton files and a TOC (`.fltoc`) from an XML object/function map.

The executable target is named `HelpFileSkeletonGenerator`.

## Highlights

- Modern C++20 codebase and build configuration
- Target-based CMake setup with stronger compiler warnings
- XML parsing via `tinyxml2`
- XML parsing isolated in `src/help_map_parser.*` for testability
- Cross-platform filesystem handling through `std::filesystem`
- Auto-generation of domain object, constructor, property, method, and function topic files

## Project Layout

- `src/`: source and CMake project definition
- `src/include/tinyxml2.*`: bundled XML parser
- `test_files/`: sample XML files for local runs
- `out/Test-Project-1/`: generated help content output tree
- `bin/`: built executable output

## Requirements

- CMake 3.21+
- A C++20-capable compiler:
  - MSVC 19.3x+ (Visual Studio 2022)
  - GCC 11+
  - Clang 13+

## Build

From the repository root:

```powershell
cmake -S src -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build --config Debug
```

Enable warnings-as-errors (recommended in CI):

```powershell
cmake -S src -B build -DHELPOMATIC_WARNINGS_AS_ERRORS=ON
cmake --build build --config Debug
```

Built executable (Windows):

- `bin/Debug/HelpFileSkeletonGenerator.exe`

## Run

The tool accepts an optional XML file path argument.

```powershell
# Uses default sample input
.\bin\Debug\HelpFileSkeletonGenerator.exe

# Or pass a specific XML map
.\bin\Debug\HelpFileSkeletonGenerator.exe .\test_files\ExtraHelpObjectMap.xml
```

Default input path (when no argument is passed):

- `../test_files/ExtraHelpObjectMap_Nanosecond.xml` (resolved from executable working directory)

## Generated Output

Output is created under:

- `out/Test-Project-1/Content/Autogenerated-Content/`
- `out/Test-Project-1/Project/TOCs/`

Subfolders include:

- `DomainObjects/`
- `Constructors/`
- `Properties/`
- `Methods/`
- `Functions/`

## Notes

- Existing generated files are not overwritten; they are skipped.
- Some generated HTML script paths are preserved for compatibility with the existing help system structure.

## Tests

The project includes CTest smoke tests for parsing and generation:

```powershell
ctest --test-dir build -C Debug --output-on-failure
```

Included smoke tests:

- `parser_smoke`: validates parsing of the sample XML map
- `generator_smoke`: runs the generator against a sample map
- `output_smoke`: verifies generated TOC/output artifacts exist

## Development

The CMake target enables stronger warnings:

- MSVC: `/W4 /permissive- /Zc:__cplusplus`
- GCC/Clang: `-Wall -Wextra -Wpedantic`

If you want stricter CI behavior, keep `HELPOMATIC_WARNINGS_AS_ERRORS=ON` in CI and `OFF` for local iteration.
